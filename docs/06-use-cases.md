# Use Cases

## UC-001: User Authentication
- **Primary Actor**: Any User (Analyst, Admin)
- **Supporting Actors**: Keycloak (OIDC Provider)
- **Preconditions**: Keycloak is operational and the user has an account.
- **Trigger**: User navigates to the AutoSOC dashboard.
- **Main Flow**: 1. System redirects to Keycloak. 2. User enters credentials. 3. Keycloak authenticates and redirects back with a token. 4. System grants access based on RBAC.
- **Alternative Flow**: User utilizes SSO via an external identity provider linked to Keycloak.
- **Failure Flow**: Invalid credentials; access denied, event logged.
- **Postconditions**: User is granted a session token.
- **Security Considerations**: Tokens must have short expiration times; HTTPS is required.

## UC-002: Data-Source Registration
- **Primary Actor**: Administrator
- **Supporting Actors**: Event-Ingestion Service
- **Preconditions**: User is logged in as Admin.
- **Trigger**: Admin wants to add a new syslog source.
- **Main Flow**: 1. Admin enters source details (IP, type). 2. System validates input. 3. System provisions an ingestion endpoint/topic. 4. System returns connection details.
- **Alternative Flow**: Admin enables synthetic event generation instead of an external source.
- **Failure Flow**: Invalid parameters; system rejects registration.
- **Postconditions**: New data source is active.
- **Security Considerations**: Only Admins can register sources to prevent unauthorized data flooding.

## UC-003: Event Ingestion
- **Primary Actor**: Event-Ingestion Service
- **Supporting Actors**: Redpanda
- **Preconditions**: Data source is registered.
- **Trigger**: External system sends a log event.
- **Main Flow**: 1. Service receives event. 2. Service validates payload size/format. 3. Service publishes to Redpanda.
- **Alternative Flow**: Batch ingestion of historical logs.
- **Failure Flow**: Malformed event is routed to Dead Letter Queue (DLQ).
- **Postconditions**: Event is queued for processing.
- **Security Considerations**: TLS required for ingestion endpoints.

## UC-004: Event Normalization
- **Primary Actor**: Processing Worker
- **Supporting Actors**: None
- **Preconditions**: Raw event is in Redpanda.
- **Trigger**: Worker pulls event from queue.
- **Main Flow**: 1. Worker parses raw fields. 2. Worker maps to OCSF-inspired schema. 3. Worker drops duplicates. 4. Worker saves to OpenSearch.
- **Alternative Flow**: Unknown schema defaults to a generic JSON blob with a "parse_error" tag.
- **Failure Flow**: Unparseable events go to DLQ.
- **Postconditions**: Normalized event is searchable in OpenSearch.
- **Security Considerations**: Ensure no code injection occurs during parsing.

## UC-005: Log Search
- **Primary Actor**: SOC Analyst
- **Supporting Actors**: OpenSearch
- **Preconditions**: Events are normalized and stored.
- **Trigger**: Analyst enters a query (e.g., `src_ip:10.0.0.5`).
- **Main Flow**: 1. System sends query to OpenSearch. 2. OpenSearch returns matched logs. 3. UI displays logs.
- **Alternative Flow**: Analyst uses saved queries.
- **Failure Flow**: OpenSearch timeout; UI displays error.
- **Postconditions**: Results are displayed.
- **Security Considerations**: Search queries must respect RBAC data segmentation if implemented.

## UC-006: Rule-Based Attack Detection
- **Primary Actor**: Detection Engine
- **Supporting Actors**: Redis (for state)
- **Preconditions**: Sigma rules are loaded.
- **Trigger**: Normalized event arrives.
- **Main Flow**: 1. Engine evaluates event against rules. 2. Match found. 3. Engine generates an alert.
- **Alternative Flow**: Match against an IoC list.
- **Failure Flow**: Rule parsing error skips the specific rule.
- **Postconditions**: Alert is generated.
- **Security Considerations**: Ensure rules cannot execute arbitrary code.

## UC-007: ML-Based Anomaly Detection
- **Primary Actor**: ML Inference Service
- **Supporting Actors**: MLflow
- **Preconditions**: ML model is active.
- **Trigger**: Normalized event arrives.
- **Main Flow**: 1. Service extracts features. 2. Model outputs anomaly score. 3. Score exceeds threshold; alert generated.
- **Alternative Flow**: N/A
- **Failure Flow**: Inference times out; event marked as unscored.
- **Postconditions**: ML alert is generated.
- **Security Considerations**: Protect model from adversarial inputs (e.g., extreme values causing DoS).

## UC-008: Potential Zero-Day Identification
- **Primary Actor**: Detection Engine
- **Supporting Actors**: ML Inference Service
- **Preconditions**: Alert generated by ML, no rule-based match.
- **Trigger**: ML anomaly score is > 95%.
- **Main Flow**: 1. System checks if event matches known rules. 2. No match found. 3. System tags alert as "Potential Zero-Day Behavior".
- **Alternative Flow**: N/A
- **Failure Flow**: Fails to tag; remains a generic anomaly.
- **Postconditions**: High-priority alert tagged for investigation.
- **Security Considerations**: Terminology must not definitively claim a zero-day without human validation.

## UC-009: Alert Investigation
- **Primary Actor**: SOC Analyst
- **Supporting Actors**: OpenSearch
- **Preconditions**: Alert exists.
- **Trigger**: Analyst clicks on an alert.
- **Main Flow**: 1. System fetches alert details. 2. Analyst views raw logs, ML explanation, and rule matches.
- **Alternative Flow**: Analyst assigns alert to another team member.
- **Failure Flow**: Database unreachable; UI shows error.
- **Postconditions**: Alert status changes to "In Progress".
- **Security Considerations**: Analyst notes must be sanitized against XSS.

## UC-010: Alert Correlation
- **Primary Actor**: Correlation Engine
- **Supporting Actors**: None
- **Preconditions**: Multiple alerts exist.
- **Trigger**: Scheduled correlation job runs (or stream processor triggers).
- **Main Flow**: 1. Engine identifies alerts with shared entities (IP, user) within a time window. 2. Engine groups them.
- **Alternative Flow**: N/A
- **Failure Flow**: Engine fails; alerts remain standalone.
- **Postconditions**: Alerts are correlated into an incident candidate.
- **Security Considerations**: Ensure correlation logic does not exhaust memory.

## UC-011: Incident Creation
- **Primary Actor**: Correlation Engine / SOC Analyst
- **Supporting Actors**: None
- **Preconditions**: Correlated alerts meet severity threshold.
- **Trigger**: Correlation engine finalizes grouping, OR Analyst clicks "Create Incident".
- **Main Flow**: 1. System creates Incident record. 2. Associates alerts and preserves immutable evidence. 3. Generates timeline.
- **Alternative Flow**: Analyst manually merges two incidents.
- **Failure Flow**: Database commit fails; rolls back.
- **Postconditions**: Incident is visible on the SOC dashboard.
- **Security Considerations**: Evidence tables must be append-only.

## UC-012: MITRE ATT&CK Mapping
- **Primary Actor**: System
- **Supporting Actors**: None
- **Preconditions**: Incident contains rule matches with MITRE tags.
- **Trigger**: Incident created.
- **Main Flow**: 1. System extracts MITRE tags from rules. 2. Maps tags to Tactics and Techniques. 3. Saves mapping to incident.
- **Alternative Flow**: Analyst manually adds a MITRE tag based on findings.
- **Failure Flow**: Rule lacks tags; mapping is empty.
- **Postconditions**: Incident has MITRE context.
- **Security Considerations**: Relies on trusted MITRE mapping data.

## UC-013: Attack-Graph Construction
- **Primary Actor**: Frontend UI
- **Supporting Actors**: Cytoscape.js
- **Preconditions**: Incident has MITRE mapping and entities.
- **Trigger**: Analyst views Incident Graph tab.
- **Main Flow**: 1. UI requests graph data. 2. Backend formats nodes (IPs) and edges (Techniques). 3. Cytoscape.js renders the interactive graph.
- **Alternative Flow**: Analyst filters graph by specific tactic.
- **Failure Flow**: Data format error; graph fails to render.
- **Postconditions**: Graph is displayed.
- **Security Considerations**: Graph data must not expose hidden entities unauthorized for the user.

## UC-014: Attack-Progression Prediction
- **Primary Actor**: ML Inference Service / Agent
- **Supporting Actors**: None
- **Preconditions**: Incident has a sequence of MITRE techniques.
- **Trigger**: Incident updated.
- **Main Flow**: 1. Service evaluates current technique sequence. 2. Predicts likely next technique based on historical models. 3. Updates incident with prediction.
- **Alternative Flow**: N/A
- **Failure Flow**: Sequence too unique; model returns low confidence, prediction hidden.
- **Postconditions**: Analyst sees "Predicted Next Step".
- **Security Considerations**: Predictions are advisory only.

## UC-015: Agentic Investigation
- **Primary Actor**: Agent Workflow (LangGraph)
- **Supporting Actors**: Ollama, OpenSearch
- **Preconditions**: Incident assigned to AI.
- **Trigger**: System auto-triggers on High severity, or Analyst clicks "Investigate via AI".
- **Main Flow**: 1. Agent formulates search query. 2. Retrieves logs from OpenSearch (RAG). 3. Synthesizes findings. 4. Posts summary to incident.
- **Alternative Flow**: Agent requests threat intel from an external mock API.
- **Failure Flow**: LLM context window exceeded; agent returns partial summary.
- **Postconditions**: Incident contains AI findings.
- **Security Considerations**: AI must not execute shell commands or direct DB modifications.

## UC-016: Risk Calculation
- **Primary Actor**: System
- **Supporting Actors**: None
- **Preconditions**: Incident data is populated.
- **Trigger**: Incident updated.
- **Main Flow**: 1. System calculates risk score based on asset criticality, alert severity, and ML confidence. 2. Updates incident risk score.
- **Alternative Flow**: Analyst overrides risk score manually.
- **Failure Flow**: Calculation error defaults to lowest bound.
- **Postconditions**: Incident displays accurate risk score.
- **Security Considerations**: Calculation logic must be auditable.

## UC-017: Response Recommendation
- **Primary Actor**: Response Engine / Agent
- **Supporting Actors**: None
- **Preconditions**: Investigation complete.
- **Trigger**: AI or rule engine identifies a containment strategy.
- **Main Flow**: 1. System matches findings to allowlisted playbooks. 2. System posts "Recommended Action: Block IP 10.0.0.5".
- **Alternative Flow**: Multiple recommendations provided for analyst choice.
- **Failure Flow**: No playbook matches; defaults to manual response.
- **Postconditions**: Recommendation is pending approval.
- **Security Considerations**: Recommendations must strictly adhere to the allowlist.

## UC-018: Analyst Response Approval
- **Primary Actor**: SOC Analyst
- **Supporting Actors**: None
- **Preconditions**: Response is recommended.
- **Trigger**: Analyst reviews recommendation.
- **Main Flow**: 1. Analyst clicks "Approve". 2. System executes playbook via integrations. 3. System logs approval. 4. Updates incident status.
- **Alternative Flow**: Analyst clicks "Reject" with a reason.
- **Failure Flow**: Playbook execution fails; status set to "Error".
- **Postconditions**: Action executed or rejected.
- **Security Considerations**: Full audit log of who approved the action is mandatory.

## UC-019: Response Execution Simulation
- **Primary Actor**: SOC Analyst
- **Supporting Actors**: Response Engine
- **Preconditions**: Response is recommended.
- **Trigger**: Analyst clicks "Simulate (Dry-Run)".
- **Main Flow**: 1. System runs playbook against mock endpoints. 2. System returns expected outcome (e.g., "Firewall rule created"). 3. Analyst reviews.
- **Alternative Flow**: N/A
- **Failure Flow**: Simulator unavailable; UI warns user.
- **Postconditions**: Simulation results displayed.
- **Security Considerations**: Simulation must never touch production infrastructure.

## UC-020: Incident-Report Generation
- **Primary Actor**: Auditor / Security Manager
- **Supporting Actors**: LLM
- **Preconditions**: Incident is closed.
- **Trigger**: User clicks "Generate Report".
- **Main Flow**: 1. System compiles evidence and timeline. 2. LLM generates technical and management summaries. 3. System outputs PDF/Markdown.
- **Alternative Flow**: Export raw data as CSV.
- **Failure Flow**: Generation fails; UI shows error.
- **Postconditions**: Report downloaded by user.
- **Security Considerations**: Report must redact PII based on the user's role.
