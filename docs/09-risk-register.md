# Risk Register

| Risk ID | Description | Category | Probability | Impact | Score (PxI) | Mitigation | Contingency | Owner | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **RSK-001** | **Incompatible dataset schemas**: Public datasets may have different formats, breaking normalization. | Data | High | High | High | Define a strict OCSF-inspired schema mapping for each dataset prior to ingestion. | Use a generic JSON fallback for unmappable fields. | Data Engineer | Open |
| **RSK-002** | **Poor model generalization**: ML models may memorize training data and fail on novel synthetic events. | AI/ML | Medium | High | High | Use cross-validation and keep a strict hold-out test set. | Retrain with a simplified feature set (e.g., Random Forest). | ML Engineer | Open |
| **RSK-003** | **Class imbalance**: Rare zero-day behaviors get swallowed by massive amounts of benign traffic. | AI/ML | High | High | High | Apply SMOTE or use anomaly detection (e.g., Isolation Forest) instead of strict classification. | Adjust decision thresholds. | ML Engineer | Open |
| **RSK-004** | **Data leakage**: Future attack labels leak into the training data timeline. | AI/ML | Low | Critical | Medium | Strictly split training/testing data temporally. | Discard contaminated models and retrain. | ML Engineer | Open |
| **RSK-005** | **Excessive false positives**: The detection engine flags too much benign traffic, causing alert fatigue. | Technical | High | Medium | Medium | Implement strict correlation rules to group alerts. Allow analysts to tune thresholds. | Disable noisy Sigma rules temporarily. | SOC Architect | Open |
| **RSK-006** | **Insufficient training hardware**: Local GPUs cannot handle the dataset size for PyTorch training. | Project | High | Medium | Medium | Sample the dataset down; use simpler models (scikit-learn). | Use cloud computing credits if available. | ML Engineer | Open |
| **RSK-007** | **Model drift**: Over time, normal network behavior changes, making the ML model inaccurate. | AI/ML | Medium | Medium | Medium | Implement drift monitoring in MLflow. | Trigger a scheduled retraining pipeline. | ML Engineer | Open |
| **RSK-008** | **Prompt injection**: Attacker crafts malicious logs designed to hijack the Agentic AI. | Security | Medium | High | High | Strip special control characters from logs before sending to the LLM context. | Disable AI summarization for specific log sources. | Sec. Engineer | Open |
| **RSK-009** | **Hallucinated incident conclusions**: LLM makes up evidence not present in the logs. | AI/ML | Medium | High | High | Force the LLM to strictly cite log IDs (RAG). Instruct analysts that AI is advisory only. | Reject the summary; require manual analyst review. | AI Engineer | Open |
| **RSK-010** | **Agent tool misuse**: LangGraph agent calls the wrong internal tool in a loop. | AI/ML | Medium | Medium | Medium | Set hard limits on tool invocation depth (e.g., max 5 steps). | Hard-kill the agent workflow. | AI Engineer | Open |
| **RSK-011** | **Sensitive-data exposure**: Real PII or credentials are leaked in the academic project repo or logs. | Security | Low | Critical | Medium | Use synthetic data. Run Gitleaks in CI/CD pipeline. | Rotate compromised keys immediately; scrub repo history. | Sec. Engineer | Open |
| **RSK-012** | **Unauthorized response actions**: The system autonomously blocks critical infrastructure without approval. | Security | Low | Critical | Medium | Hardcode a requirement for human click-approval in the response engine. | Use emergency rollback playbook. | SOC Architect | Open |
| **RSK-013** | **OpenSearch resource consumption**: Index bloat crashes the local Docker environment. | Technical | High | High | High | Set strict data retention policies (e.g., delete logs older than 7 days in dev). | Purge indices manually and restart. | DevOps Eng. | Open |
| **RSK-014** | **Event-stream backlog**: Processing workers cannot keep up with Redpanda topic ingestion. | Technical | Medium | Medium | Medium | Scale out FastAPI processing workers. | Throttle synthetic event generation. | Software Eng. | Open |
| **RSK-015** | **Service integration failure**: Keycloak, OpenSearch, and FastAPI fail to communicate in Docker. | Integration | Medium | High | High | Use strict docker-compose healthchecks and network aliases. | Manually restart failed containers. | DevOps Eng. | Open |
| **RSK-016** | **Scope expansion**: Adding too many features prevents project completion. | Project | High | High | High | Strictly adhere to the MVP definition and Definition of Done. | Cut optional features (e.g., predictive mapping). | Project Lead | Open |
| **RSK-017** | **Schedule delay**: Core components take longer than the academic semester allows. | Project | Medium | High | High | Track progress weekly against Epics. | Reduce UI complexity; focus on backend APIs. | Project Lead | Open |
| **RSK-018** | **Incomplete documentation**: Rushing coding leaves the project undocumented and undefendable. | Project | Medium | High | High | Documentation is required in the Definition of Done for every PR. | Dedicate the final 2 weeks solely to docs. | Tech Writer | Open |
| **RSK-019** | **Failed final demonstration**: The live demo breaks during the academic presentation. | Project | Low | Critical | Medium | Pre-record a video demonstration. Have a frozen, stable branch ready. | Present the recorded video instead. | Project Lead | Open |
