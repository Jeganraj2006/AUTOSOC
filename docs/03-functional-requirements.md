# Functional Requirements

## Authentication and Authorization
| Identifier | FR-AUTH-001 |
| :--- | :--- |
| **Requirement** | The system must authenticate users via OIDC using Keycloak and enforce Role-Based Access Control (RBAC). |
| **Actor** | Any User |
| **Priority** | High |
| **Preconditions** | Keycloak server is running and accessible. |
| **Expected Behavior** | Users are redirected to Keycloak for login. Upon success, they are assigned permissions based on their role (Admin, Analyst, Manager, Auditor). |
| **Failure Behavior** | Access is denied, and an unauthorized event is logged. |
| **Acceptance Criteria** | 1. User cannot access the dashboard without a valid token. 2. Auditors cannot perform write actions. |
| **Dependencies** | Keycloak |

## Event Ingestion
| Identifier | FR-INGEST-001 |
| :--- | :--- |
| **Requirement** | The system must ingest Linux Syslog, Windows event-log samples, Network-flow, Kubernetes audit-logs, and AWS CloudTrail logs via Redpanda. |
| **Actor** | Event-Ingestion Service |
| **Priority** | High |
| **Preconditions** | Redpanda cluster is operational. |
| **Expected Behavior** | Ingestion endpoints receive events, perform initial schema validation, and publish them to appropriate Redpanda topics. |
| **Failure Behavior** | Invalid events are routed to a dead-letter queue (DLQ); ingestion failures are logged. |
| **Acceptance Criteria** | 1. 1000 synthetic events of each type are successfully ingested and routed. 2. Malformed events end up in the DLQ. |
| **Dependencies** | Redpanda |

| Identifier | FR-INGEST-002 |
| :--- | :--- |
| **Requirement** | The system must generate synthetic security-events for demonstration purposes. |
| **Actor** | Administrator / Event-Ingestion Service |
| **Priority** | Medium |
| **Preconditions** | Synthetic generation module is configured. |
| **Expected Behavior** | The system generates realistic, mock security logs at a configurable rate. |
| **Failure Behavior** | Generation halts; an error is logged. |
| **Acceptance Criteria** | 1. Admin can trigger generation of 500 logs per minute. 2. Logs conform to expected formats. |
| **Dependencies** | None |

## Data Processing
| Identifier | FR-PROC-001 |
| :--- | :--- |
| **Requirement** | The system must normalize incoming events to an OCSF-inspired schema and deduplicate them. |
| **Actor** | Processing Worker |
| **Priority** | High |
| **Preconditions** | Events exist in Redpanda topics. |
| **Expected Behavior** | Events are mapped to common fields (e.g., src_ip, dest_ip, timestamp), enriched with threat intel, and stored in PostgreSQL and OpenSearch. |
| **Failure Behavior** | Unmappable events are flagged and sent to DLQ. |
| **Acceptance Criteria** | 1. Different log sources result in a unified JSON structure in OpenSearch. 2. Duplicate events within a 1-second window are dropped. |
| **Dependencies** | PostgreSQL, OpenSearch |

## Detection
| Identifier | FR-DETECT-001 |
| :--- | :--- |
| **Requirement** | The system must evaluate normalized events against rule-based threat detection (Sigma-style rules) and IoCs. |
| **Actor** | Detection Engine |
| **Priority** | High |
| **Preconditions** | Rules are loaded into the engine. |
| **Expected Behavior** | Matches generate an alert with severity and category. |
| **Failure Behavior** | The event processing continues; detection failure is logged for the specific rule. |
| **Acceptance Criteria** | 1. A known malicious IP generates a High severity alert. |
| **Dependencies** | FR-PROC-001 |

| Identifier | FR-ML-001 |
| :--- | :--- |
| **Requirement** | The system must use ML classification to detect behavior-based anomalies and identify potential zero-day behaviors. |
| **Actor** | ML Inference Service |
| **Priority** | High |
| **Preconditions** | ML model is deployed and registered in MLflow. |
| **Expected Behavior** | Events scored as highly anomalous that do not match known signatures are flagged as "potential zero-day behavior" with a confidence score. |
| **Failure Behavior** | If inference fails, the event is marked as "Unscored" and standard rule processing applies. |
| **Acceptance Criteria** | 1. The system outputs a confidence score (0-100) for anomaly classification. 2. Exceeding the anomaly threshold triggers an alert. |
| **Dependencies** | PyTorch, MLflow |

## Incident Management
| Identifier | FR-INCIDENT-001 |
| :--- | :--- |
| **Requirement** | The system must correlate related alerts into a single incident and generate an incident timeline. |
| **Actor** | Correlation Engine |
| **Priority** | High |
| **Preconditions** | Alerts are generated by the Detection Engine. |
| **Expected Behavior** | Alerts sharing entities (e.g., same IP, user) within a time window are grouped. Evidence is preserved immutably. |
| **Failure Behavior** | Alerts remain un-correlated as individual items. |
| **Acceptance Criteria** | 1. 5 alerts for the same source IP over 10 minutes form 1 incident. 2. Incident page displays a chronological timeline. |
| **Dependencies** | FR-DETECT-001, PostgreSQL |

| Identifier | FR-INCIDENT-002 |
| :--- | :--- |
| **Requirement** | The system must map incidents to MITRE ATT&CK tactics/techniques and display an interactive attack-graph. |
| **Actor** | SOC Analyst |
| **Priority** | Medium |
| **Preconditions** | Incident contains mapped entity data. |
| **Expected Behavior** | The UI displays a Cytoscape.js graph showing the sequence of techniques. |
| **Failure Behavior** | Graph renders empty with a "No mapping available" message. |
| **Acceptance Criteria** | 1. Analyst can view a graph with nodes representing assets and edges representing techniques. |
| **Dependencies** | Cytoscape.js |

## Agentic AI
| Identifier | FR-AGENT-001 |
| :--- | :--- |
| **Requirement** | The system must support Agentic AI-based investigation that queries logs, predicts attack-progression, and assesses risk. |
| **Actor** | Agent Workflow |
| **Priority** | High |
| **Preconditions** | Local LLM (Ollama) is running; LangGraph orchestrator is active. |
| **Expected Behavior** | The agent executes a workflow to gather context from OpenSearch, predicts the likely next technique, calculates risk, and generates technical/management summaries. |
| **Failure Behavior** | Agent fails gracefully, returning a "Manual investigation required" flag. |
| **Acceptance Criteria** | 1. Agent produces a summary citing specific log entries. 2. Agent predicts at least 1 plausible next MITRE technique. |
| **Dependencies** | LangGraph, Ollama, OpenSearch |

## Response and Approval
| Identifier | FR-RESPONSE-001 |
| :--- | :--- |
| **Requirement** | The system must recommend controlled response actions and allow a dry-run simulation. |
| **Actor** | Response Engine / SOC Analyst |
| **Priority** | High |
| **Preconditions** | Agentic AI has investigated the incident. |
| **Expected Behavior** | The system presents allowlisted playbooks (e.g., "Block IP"). The analyst can click "Simulate" to see expected outcomes, then "Approve" or "Reject". |
| **Failure Behavior** | System defaults to "No automatic response recommended". |
| **Acceptance Criteria** | 1. Response actions require explicit click approval. 2. Simulated results are displayed before execution. |
| **Dependencies** | FR-AGENT-001 |

| Identifier | FR-RESPONSE-002 |
| :--- | :--- |
| **Requirement** | The system must support rollback of executed response actions where applicable. |
| **Actor** | SOC Analyst |
| **Priority** | Medium |
| **Preconditions** | A reversible response action was executed. |
| **Expected Behavior** | Analyst clicks "Rollback"; the system reverses the action (e.g., unblocks an IP). |
| **Failure Behavior** | Rollback fails, alerting the Administrator for manual intervention. |
| **Acceptance Criteria** | 1. Executed playbook state changes to "Rolled Back" upon success. |
| **Dependencies** | FR-RESPONSE-001 |

## Reporting
| Identifier | FR-REPORT-001 |
| :--- | :--- |
| **Requirement** | The system must generate security reports, exports, and maintain a complete audit log of all system and user actions. |
| **Actor** | Security Manager / Auditor |
| **Priority** | High |
| **Preconditions** | System has accumulated data. |
| **Expected Behavior** | Users can export incident summaries to PDF/CSV. Audit logs track every login, approval, and configuration change. |
| **Failure Behavior** | Export returns an error; audit logging failure halts the related user action. |
| **Acceptance Criteria** | 1. Auditor can view a read-only log of which analyst approved which response. |
| **Dependencies** | PostgreSQL |
