# Non-Functional Requirements

## Security and Privacy
| Identifier | NFR-SEC-001 |
| :--- | :--- |
| **Category** | Security / Agent Safety |
| **Requirement** | AI Agents must not have unrestricted access to execute shell commands, run destructive exploit code, or perform autonomous containment without human approval. |
| **Measurement Target** | 0 instances of autonomous write/execute actions outside allowlisted, user-approved playbooks. |

| Identifier | NFR-SEC-002 |
| :--- | :--- |
| **Category** | Privacy |
| **Requirement** | Sensitive information (e.g., PII, real passwords) must be masked before being sent to any LLM. |
| **Measurement Target** | 100% of defined PII fields are redacted in logs passed to the LangGraph context. |

| Identifier | NFR-SEC-003 |
| :--- | :--- |
| **Category** | Data Integrity |
| **Requirement** | Incident evidence and audit logs must be immutable once written to the database. |
| **Measurement Target** | Application logic strictly prohibits UPDATE/DELETE statements on the `audit_logs` and `incident_evidence` tables. |

## Performance and Scalability
| Identifier | NFR-PERF-001 |
| :--- | :--- |
| **Category** | Performance |
| **Requirement** | The system must sustain an event ingestion throughput suitable for an academic prototype. |
| **Measurement Target** | Ingest, validate, and normalize 1,000 events per second (EPS) on a standard 4-core, 16GB RAM environment. |

| Identifier | NFR-PERF-002 |
| :--- | :--- |
| **Category** | Performance |
| **Requirement** | The API response time for SOC dashboard queries (e.g., listing incidents) must be fast to ensure UI responsiveness. |
| **Measurement Target** | 95th percentile (P95) API response time < 500ms for standard database queries. |

| Identifier | NFR-PERF-003 |
| :--- | :--- |
| **Category** | Performance |
| **Requirement** | OpenSearch log search queries must return results within an acceptable timeframe. |
| **Measurement Target** | Log searches over a 7-day window (approx. 10 million synthetic logs) return in < 2 seconds. |

## Availability and Reliability
| Identifier | NFR-REL-001 |
| :--- | :--- |
| **Category** | Reliability |
| **Requirement** | The event processing pipeline must handle temporary downstream database outages without data loss. |
| **Measurement Target** | Redpanda buffers events for at least 24 hours. The pipeline automatically recovers and processes the backlog upon database restoration. |

| Identifier | NFR-REL-002 |
| :--- | :--- |
| **Category** | Disaster Recovery |
| **Requirement** | The system must support automated backups of the PostgreSQL relational database. |
| **Measurement Target** | Daily automated pg_dump backups configured in the Kubernetes deployment. |

## Maintainability and Testability
| Identifier | NFR-MAINT-001 |
| :--- | :--- |
| **Category** | Testability |
| **Requirement** | The backend codebase must maintain a high level of test coverage. |
| **Measurement Target** | Minimum 80% line coverage for Python backend code via Pytest. |

| Identifier | NFR-MAINT-002 |
| :--- | :--- |
| **Category** | Maintainability / Portability |
| **Requirement** | The system must be fully containerized and reproducible across different host operating systems. |
| **Measurement Target** | `docker-compose up` completely provisions the local MVP without manual OS-level package installations. |

| Identifier | NFR-MAINT-003 |
| :--- | :--- |
| **Category** | Documentation |
| **Requirement** | The system architecture, API endpoints, and deployment steps must be thoroughly documented. |
| **Measurement Target** | 100% of FastAPI endpoints are documented via Swagger/OpenAPI. Readme includes setup steps. |

## Observability and AI Specifics
| Identifier | NFR-OBS-001 |
| :--- | :--- |
| **Category** | Observability |
| **Requirement** | Application metrics, traces, and logs must be centralized. |
| **Measurement Target** | OpenTelemetry instruments all FastAPI services; metrics are scraped by Prometheus and visible in Grafana. |

| Identifier | NFR-AI-001 |
| :--- | :--- |
| **Category** | Model Reproducibility |
| **Requirement** | Machine learning model training runs must be tracked and reproducible. |
| **Measurement Target** | MLflow logs parameters, metrics, and model artifacts for 100% of training runs. |

| Identifier | NFR-AI-002 |
| :--- | :--- |
| **Category** | Model Explainability |
| **Requirement** | Machine learning anomaly detection must provide explainable features to the Analyst. |
| **Measurement Target** | Alerts generated by the ML model include top-3 contributing feature weights (e.g., "High byte count, unusual port"). |
